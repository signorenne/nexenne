#+OPTIONS: toc:2 num:nil ^:nil
#+STARTUP: showall

Owns the repo-level architecture: how modules, CMake targets, examples, tests,
docs, and install rules fit together. For the exact file layout see
[[file:file-system.org][file-system.org]]. For CMake details see
[[file:setup/build-system.org][setup/build-system.org]] and
[[file:setup/cmake-helpers.org][setup/cmake-helpers.org]].

* Shape

nexenne is a C++23 module monorepo. The root project discovers modules under
=modules/=, topologically orders them from =module.deps=, and adds each enabled
module as a CMake subdirectory. Each module exports a target
=nexenne::<name>= and a namespace =nexenne::<name>=.

Header-only modules are the default. A module becomes compiled only when it has
a real reason to own sources, ABI, or private implementation.

* Build graph

#+BEGIN_SRC text
CMakeLists.txt
  |
  +-- cmake/nexenne_modules.cmake
  |     |
  |     +-- discover modules under modules/
  |     +-- read module.deps
  |     `-- order modules by dependency
  |
  +-- cmake/nexenne_module.cmake
  |     `-- nexenne_add_module(<name> ...) declares nexenne::<name>
  |
  +-- modules/<name>/CMakeLists.txt
  |     |
  |     +-- nexenne_add_module(<name> ...)
  |     +-- tests/ when NEXENNE_BUILD_TESTS=ON
  |     `-- doc/ when NEXENNE_BUILD_DOCS=ON
  |
  +-- examples/ when NEXENNE_BUILD_EXAMPLES=ON
  `-- install rules when NEXENNE_INSTALL=ON
#+END_SRC

The aggregate target =nexenne::all= links every enabled module. Consumers that
only want a subset should link the specific module targets instead.

* Module contract

A module is responsible for:

- Public headers under =include/nexenne/<name>/=.
- A module umbrella header =<name>.hpp=.
- Optional =module.deps= listing nexenne module dependencies.
- Tests that exercise public behavior.
- Doxygen build files for generated API reference.
- Guides under =doc/module/<name>/=.
- Examples under =examples/<name>/= when it has public usage to show.

The root owns discovery and install aggregation. The module owns its own public
surface.

* Dependency flow

Dependencies flow downward through the module layer graph. =module.deps= is read
by both the root build and module helper, so it must be the only source of truth
for nexenne inter-module dependencies. External dependencies are declared in the
module CMake call only when they are not nexenne modules.

* Tests and examples

doctest binaries are built per module. The aggregate =nexenne_tests= target
builds and runs each module's suite. Examples are normal executables under
=examples/<name>/= and link the module they demonstrate plus =nexenne::warnings=.

Tests prove behavior. Examples teach usage. Do not make one substitute for the
other.

* Documentation layers

- Root hubs explain direction, design, agent rules, style, and workflow.
- =doc/setup/= explains infrastructure.
- =doc/module/README.org= lists modules and dependency layering.
- =doc/module/<name>/README.org= lists one module's public surface.
- =doc/module/<name>/<topic>.org= explains one component or topic group.
- Doxygen generates API reference from public headers.

The Org guides and Doxygen reference are parallel outputs from the same public
surface. Keep them aligned in the same change.

* Install and consumption

nexenne supports:

- =find_package(nexenne REQUIRED)= for the whole library.
- =find_package(nexenne REQUIRED COMPONENTS <name>)= for selected modules.
- =find_package(nexenne-<name> REQUIRED)= for a single module package.
- =add_subdirectory= or =FetchContent= for source consumption.

The install smoke script builds a throwaway consumer to verify these paths.

* Architecture rules

- Add a module directory instead of editing a central module registry.
- Add a dependency to =module.deps= instead of duplicating it in root CMake.
- Keep module APIs under their namespace; shared implementation details go in
  =detail= namespaces.
- Keep examples and tests outside installed public headers.
- Do not let generated docs become the only source for public behavior.
