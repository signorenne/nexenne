Start here to find the right file for the work in front of you, then load only
what the role and touched area require. Every doc has one job and one owner. If
a concept lives in two places, one of them is stale: keep the floor in the hub
and the full reference in the owning spoke.

Role names:

- /scout/ maps the repo area and finds owners.
- /planner/ decides scope, sequencing, commands, and risk.
- /impl/ changes code, tests, examples, and docs.
- /review/ checks behavior, maintainability, and missing coverage.
- /module/ adds or reshapes a module.
- /onboard/ learns how to build, use, and navigate the project.

* Reference map

The graph is hub and spoke, not a lateral web.

- [[file:../AGENTS.md][AGENTS.md]] is the code hub. It holds the working-memory
  floor for AI agents and humans: where work goes, execution recipes, hard
  rules, validation commands, and review checklist.
- Tool-specific bridges such as [[file:../CLAUDE.md][CLAUDE.md]],
  [[file:../GEMINI.md][GEMINI.md]], and
  [[file:../.github/copilot-instructions.md][.github/copilot-instructions.md]]
  point back to [[file:../AGENTS.md][AGENTS.md]] so every assistant uses the same
  rules.
- [[file:../VISION.org][VISION.org]] owns project direction, principles, and
  non-goals.
- [[file:../DESIGN.org][DESIGN.org]] owns API and library surface design.
- [[file:../STYLE_GUIDE.org][STYLE_GUIDE.org]] owns C++ style and public API
  documentation mechanics. Other docs can quote a one-line floor and link back.
- [[file:../CONTRIBUTING.org][CONTRIBUTING.org]] owns workflow, component-change
  steps, commit subjects, hooks, CI, and PR gates.
- [[file:glossary.org][glossary.org]] owns canonical terms.
- [[file:writing.org][writing.org]] owns prose style, punctuation, and human-facing
  text rules.
- [[file:file-system.org][file-system.org]] owns where files go.
- [[file:architecture.org][architecture.org]] owns the repo-level build and module
  architecture.
- [[file:dependencies.org][dependencies.org]] owns dependency policy.
- [[file:agent-workflows.org][agent-workflows.org]] owns reusable multi-step task
  playbooks for agents.
- [[file:setup/README.org][setup/]] owns infrastructure deep dives: CMake,
  modules, testing, install, API docs, hooks, CI,
  conventions, and tools.
- [[file:module/README.org][module/]] owns the library catalogue. A module index
  owns the public surface of that module. A component leaf owns the narrative
  guide for one component or tightly grouped set of components.
- [[file:../template/MODULE_GUIDE.org][template/MODULE_GUIDE.org]] owns the new-module
  runbook and PR checklist.

Hubs may restate a rule in one short line when an agent must keep it in memory.
The explanation, examples, and edge cases live in the owning spoke. Spokes link
to each other instead of copying paragraphs.

* Guidelines for future additions

- /Single source per concept./ One doc owns the fact. Everywhere else links to
  that doc.
- /Org mode plus agent entrypoints./ Prose docs use =.org=. Do not add =.md=
  docs, except =AGENTS.md= and tiny tool-specific bridge files such as
  =CLAUDE.md=, =GEMINI.md=, and =.github/copilot-instructions.md=. =AGENTS.md=
  is canonical; bridge files must not duplicate rules.
- /Naming./ Root hubs are uppercase words or established root names
  (=AGENTS.md=, =CLAUDE.md=, =GEMINI.md=, =STYLE_GUIDE.org=,
  =CONTRIBUTING.org=, =README.org=). Setup topics use hyphen-case under
  =doc/setup/=. Module leaf docs follow the public component name when it is
  one component (=static_vector.org=) and hyphen-case when the guide covers a
  topic group (=string-matching.org=).
- /Register new docs./ Root docs and setup docs are registered in this file.
  Module leaves are registered in their module README. New modules are
  registered in [[file:module/README.org][doc/module/README.org]].
- /Header pointer./ Open each doc with a short statement of what it owns and
  links to the related hub or next deep dive.
- /Inline is floor, extract is reference./ Keep only the rule an agent must hold
  in a hub. Put examples and edge cases in the owning spoke.
- /Split threshold./ Split only when a doc is longer than one screen and has at
  least three subtopics that can be loaded independently.
- /Public API doc set./ A public component change normally touches the header
  Doxygen, doctest suite, runnable example, Org guide, module README, and CMake
  lists that enumerate those files.
