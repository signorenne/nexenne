#+TITLE: Continuous integration
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

[[file:../../.github/workflows/ci.yml][.github/workflows/ci.yml]] runs on every
push and pull request to =main=. A PR merges only when every job is green.
Concurrency is set so a new push to a ref cancels the in-flight run for it. All
jobs run on =ubuntu-24.04=; the compile-heavy ones cache with ccache via
=-DCMAKE_CXX_COMPILER_LAUNCHER=ccache=.

| job           | toolchain       | what it checks                                                            |
|---------------+-----------------+---------------------------------------------------------------------------|
| =sync=        | bash            | every module is registered in the docs, examples, and its umbrella header |
| =format=      | clang-format-20 | =clang-format-20 --dry-run --Werror= on all tracked =.hpp= / =.cpp=       |
| =build-test=  | gcc-15          | =ci= preset configure + build + =ctest=, warnings as errors               |
| =build-clang= | clang-20        | =ci= preset configure + build + =ctest= (portability)                     |
| =asan=        | gcc-15          | =asan= preset build + =ctest= under Address + UB sanitizers               |
| =tidy=        | clang-20        | clang-tidy over module tests and examples from the =dev= compile database |
| =docs=        | gcc-15          | Doxygen build of =nexenne_docs= with no documentation errors              |
| =install=     | gcc-15          | install to a temp prefix, then a consumer =find_package=es a module       |

* Job notes

- =sync= runs [[file:../../scripts/check_sync.sh][scripts/check_sync.sh]]. The
  build discovers modules from the filesystem, but the docs and the umbrella
  headers are hand-written, so they can fall behind a new module or a new header
  without any build failing. The check requires, per module: a row in
  [[file:../README.org][doc/README.org]], a catalogue entry in
  [[file:../module/README.org][doc/module/README.org]] whose stated dependencies
  match =module.deps=, a doc index, an examples directory, and a mention of
  every public header in the module umbrella. A header deliberately left out of
  the umbrella still has to be named there, so the omission reads as a decision.
  Run it locally with =bash scripts/check_sync.sh=.
- =build-test= and =build-clang= use the =ci= preset, so they configure and
  build with =NEXENNE_WARNINGS_AS_ERRORS=ON=. =build-clang= exists purely to
  catch Clang-only diagnostics and portability issues.
- =tidy= configures with the =dev= preset first (it needs
  =compile_commands.json=), then lints module tests with
  =.clang-tidy-tests= and examples with the regular config.
- =docs= configures a separate =build/docs= tree with =-DNEXENNE_BUILD_DOCS=ON
  -DNEXENNE_FETCH_DOXYGEN_IF_MISSING=OFF -DNEXENNE_BUILD_TESTS=OFF= and uses the
  distro Doxygen package, so a missing Doxygen fails the job rather than
  downloading the prebuilt fallback. See [[file:api-docs.org][API docs]].
- =install= runs [[file:../../scripts/install_smoke.sh][scripts/install_smoke.sh]],
  which installs the project to a temp prefix and then consumes it: every real
  module umbrella and the generated repo umbrella must compile against the
  prefix alone, a throwaway scaffolded module must resolve both as
  =find_package(nexenne-<mod>)= and =find_package(nexenne COMPONENTS <mod>)=,
  and a second consumer must link =nexenne::all= after a full
  =find_package(nexenne)=. The umbrella compiles are the load-bearing part: the
  in-tree build compiles against the whole include directory, so a header
  missing from a target's install file set is invisible until something consumes
  the installed prefix. Run it locally the same way:
  =bash scripts/install_smoke.sh=. See [[file:install.org][Install and consume]].

* Toolchain notes

- CI builds with GCC 15 and Clang 19. The project is otherwise tested on GCC
  15.2. Bump the workflow when a module needs a feature only newer compilers
  provide.
- The =docs= job catches Doxygen documentation /errors/ (a bad =@param=, a
  =@return= on a =void= function, a broken reference), not completeness.
  "Every public symbol documented" stays a review item, see
  [[file:api-docs.org][API docs]].

* Local mirror

The =ci= preset reproduces =build-test= locally, and the pre-push hook runs
exactly it before code leaves the machine:

#+BEGIN_SRC sh
cmake --preset ci
cmake --build --preset ci
ctest --preset ci
#+END_SRC

* Release workflows

Release automation lives next to CI but is separate from the merge gate:

| workflow | purpose |
|----------+---------|
| =release-pr= | prepares snapshot or module release PRs from =main= |
| =release-candidate= | publishes =vX.Y.Z-rc.N= or =nexenne-<module>-vX.Y.Z-rc.N= prereleases |
| =publish-release= | tags and publishes a stable release after a release PR merges |

See [[file:release.org][Release and versioning]] for the maintainer flow.
