#+TITLE: nexenne glossary
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

Canonical term definitions for code, docs, issues, and agent plans. Use these
terms consistently; do not coin a synonym in a local doc when the glossary
already names the concept.

| Term                    | Definition                                                                                                                                                            |
|-------------------------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| module                  | A library under =modules/<name>/=, exported as target =nexenne::<name>= and namespace =nexenne::<name>=.                                                              |
| component               | One public type, function family, or tightly related topic inside a module. A component normally has a public header, doctest coverage, an example, and an Org guide. |
| public header           | A header installed or exposed under =modules/<mod>/include/nexenne/<mod>/=. It must follow the style guide and carry Doxygen for public symbols.                      |
| leaf header             | A public header for one component, included by the module umbrella header.                                                                                            |
| module umbrella header  | =modules/<mod>/include/nexenne/<mod>/<mod>.hpp=. It includes every public leaf header in that module.                                                                 |
| repo umbrella header    | =nexenne/nexenne.hpp=, generated at configure time from the enabled modules. It includes all enabled module umbrella headers for users who take the whole library.     |
| module.deps             | The one source of truth for nexenne inter-module dependencies, stored at =modules/<mod>/module.deps= with one dependency module name per line.                        |
| dependency layer        | The acyclic ordering enforced by module discovery. A module may only depend on lower layers.                                                                          |
| setup doc               | An infrastructure article under =doc/setup/= that explains build, testing, install, CI, tools, or conventions.                                                        |
| module index            | =doc/module/<mod>/README.org=. It owns the module's purpose, public surface, and links to component guides and examples.                                              |
| component guide         | =doc/module/<mod>/<topic>.org=. It explains purpose, idea, tradeoffs, usage, and references for one component or topic group.                                         |
| API reference           | Generated Doxygen documentation from public header comments. It complements the Org guides.                                                                           |
| doctest suite           | The module test binary built from files under =modules/<mod>/tests/= through =nexenne_add_module_tests=.                                                              |
| example                 | A runnable program under =examples/<mod>/= that demonstrates public usage.                                                                                            |
| preset                  | A CMake preset from =CMakePresets.json=, such as =dev=, =ci=, =asan=, or =release=.                                                                                   |
| top-level build         | A build where nexenne is the root CMake project. Tests, examples, and install rules default to ON here.                                                               |
| embedded build          | A build where a consumer adds nexenne through =add_subdirectory= or =FetchContent=. Tests and examples default to OFF here.                                           |
| standalone module build | A build that configures =modules/<mod>/= directly. The module bootstraps helpers and pulls sibling dependencies from =module.deps=.                                   |
| recoverable error       | A failure expected from caller-provided input. It returns =std::expected<T, error_t>=.                                                                                |
| absence                 | A valid "no result" answer, such as a ray missing a shape. It returns =std::optional<T>=, not =std::expected=.                                                        |
| precondition            | A caller obligation documented with =@pre=. Violating it is a programming error, not a recoverable runtime result.                                                    |
| guide set               | The docs, tests, examples, Doxygen, and CMake wiring that travel with a public component.                                                                             |
