#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

* Purpose

=nexenne::utility::type_list<Ts...>= is a compile-time list of types plus a
family of =tl_= metafunctions that query and transform it. Every operation runs
during compilation and produces no runtime code, so it is the vocabulary for
reasoning about a fixed set of types: the alternatives of a tagged union, a
registry of message or handler types, the element types of a tuple-like
structure.

* The problem it solves

Template metaprogramming over a set of types tends to be written as one-off
variadic recursion inline at each use, which is hard to read, easy to get wrong,
and impossible to reuse. The standard library carries type packs inside value
containers (=std::tuple=, =std::variant=) and offers =std::tuple_element= and
=std::variant_alternative=, but there is no free-standing "list of types" with a
catalogue of operations for /reasoning about the types themselves/, with no
objects involved.

=type_list= is that free-standing list. It turns ad-hoc recursion into named,
reusable building blocks: index a type, test membership, append, concatenate,
filter, deduplicate, map, all at compile time.

* How it works

** A pure type-level tag

=type_list<Ts...>= is an empty =struct= with no members: the pack lives entirely
in the type, so the list occupies no storage and runs no code, and no element is
ever instantiated. Each metafunction is a class template specialised on
=type_list<Ts...>= so it can see the pack, and each follows one of the two
standard-library conventions:

- a /query/ (=tl_size=, =tl_contains=, =tl_index_of=) derives from a
  =std::integral_constant= or =std::bool_constant= and exposes =::value=,
  surfaced as a =_v= variable template,
- a /transform/ (=tl_at=, =tl_push_back=, =tl_push_front=, =tl_concat=,
  =tl_transform=, =tl_filter=, =tl_unique=) exposes a nested =::type=, surfaced
  as a =_t= alias.

Internally they use pack tricks where possible and head-by-tail recursion where
not: =tl_contains= is a fold =(std::is_same_v<T, Ts> || ...)=, =tl_concat= and
the push operations respell the pack directly, while =tl_at=, =tl_filter=, and
=tl_unique= recurse through a =detail= helper carrying an accumulator list.
=tl_transform= and =tl_filter= take a class template (a unary trait exposing
=::type=, or a predicate exposing =::value=) and apply it across the pack.

** The metafunction catalogue

| metafunction        | kind      | result                                    |
|---------------------+-----------+-------------------------------------------|
| =tl_size_v<L>=      | query     | element count                             |
| =tl_at_t<L, N>=     | transform | the =N=-th element type                   |
| =tl_contains_v<L,T>=| query     | whether =T= is in the list                |
| =tl_index_of_v<L,T>=| query     | index of the first =T=                     |
| =tl_push_back_t=    | transform | append =T=                                |
| =tl_push_front_t=   | transform | prepend =T=                               |
| =tl_concat_t<A, B>= | transform | =A='s elements followed by =B='s          |
| =tl_transform_t=    | transform | apply a unary trait =F= to each element   |
| =tl_filter_t=       | transform | keep elements satisfying a predicate      |
| =tl_unique_t<L>=    | transform | drop later duplicates, keep the first     |

Misuse is caught at compile time: an out-of-range =tl_at= and an absent
=tl_index_of= each fire a =static_assert= with a named message, rather than a
SFINAE-friendly failure.

* API tour

Query with the =_v= variable templates (=tl_size_v=, =tl_contains_v=,
=tl_index_of_v=); build derived lists with the =_t= aliases (=tl_at_t=,
=tl_push_back_t=, =tl_push_front_t=, =tl_concat_t=, =tl_transform_t=,
=tl_filter_t=, =tl_unique_t=). =tl_index_of_v= is the workhorse: it assigns each
registered type a stable zero-based index usable as a wire tag, a variant index,
or a slot number, and =tl_contains_v= gates compile-time dispatch.

* Usage

#+BEGIN_SRC cpp
namespace nu = nexenne::utility;

using protocol = nu::type_list<connect, ping, telemetry, disconnect>;

static_assert(nu::tl_size_v<protocol> == 4);
static_assert(nu::tl_contains_v<protocol, ping>);
static_assert(nu::tl_index_of_v<protocol, disconnect> == 3);   // stable wire id

// Filter carves out the payload-free control messages at compile time.
using control = nu::tl_filter_t<protocol, std::is_empty>;
static_assert(nu::tl_size_v<control> == 3);                    // telemetry has a payload

// Concatenate then deduplicate.
using deduped = nu::tl_unique_t<nu::tl_concat_t<protocol, protocol>>;
static_assert(nu::tl_size_v<deduped> == 4);
#+END_SRC

* Pitfalls

- *Everything is type-level.* There are no runtime values; you index with types
  and constants, not variables.
- *=tl_index_of= returns the first occurrence.* On a list with duplicates the
  type-to-index map is not a bijection; run =tl_unique_t= first if you need one.
- *Out-of-range =tl_at= and absent =tl_index_of= are hard errors* (=static_assert=),
  not SFINAE fallbacks; guard with =tl_contains_v= when an absent type is a
  legitimate case.
- *=tl_transform='s =F= must expose a nested =::type= for every element and
  =tl_filter='s =Pred= a =::value=.* A plain alias template will not do; wrap it
  in a struct with the member.

* Comparison with alternatives

| library                   | scope                        | in this repo |
|---------------------------+------------------------------+--------------|
| =type_list= (this)        | small, named =tl_= catalogue | yes          |
| =boost::mp11=             | full type-list algebra       | dependency   |
| =boost::hana=             | value + type computation     | dependency   |
| =std::tuple= / =variant=  | store values of the types    | standard     |

If you only need to /store/ values of the types, a =std::tuple= or
=std::variant= already carries the pack and offers =std::get= and
=std::variant_alternative=; =type_list= is for reasoning about the types
themselves. For a single ad-hoc fold, a bare pack expansion is simpler; the value
here is the named, reusable vocabulary. =boost::mp11= and =boost::hana= offer a
much larger algebra if you are willing to take the dependency; =type_list= stays
deliberately small and covers what nexenne needs.
