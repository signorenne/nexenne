#+TITLE: discard
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

* Purpose

=nexenne::utility::discard= evaluates its arguments and throws the results away.
It is the explicit, greppable replacement for the =(void)expr= and
=static_cast<void>(expr)= idioms, both of which the style guide bans.

* The problem it solves

Sometimes a value must be computed but not used: a =[[nodiscard]]= result the
caller genuinely does not need, an expression evaluated only for its side
effect, or a variable kept alive on purpose whose name a reader might otherwise
delete as dead code. The C and C++ tradition is to write =(void)x= or
=static_cast<void>(x)=. This repo bans both, for two reasons:

- A cast is a smell. =(void)x= and =static_cast<void>(x)= read as type
  surgery, not as intent, and they are easy to skim past in review. A named call
  says what is happening: this value is deliberately dropped.
- Casts to =void= are hard to search for and easy to overload with other
  meanings. A single named function is one thing to grep, one thing to audit,
  and one place to hang a comment.

=discard= turns the drop into a verb: the intent lives in the name, not hidden
in a cast.

* How it works

=discard= is a single variadic function template:

#+BEGIN_EXAMPLE
template <typename... Ts>
constexpr auto discard(Ts&&... args) noexcept -> void {}
#+END_EXAMPLE

Each argument is evaluated at the call site, so side effects happen and any
exception thrown while computing an argument still propagates. Each is bound to
a forwarding reference and then ignored because the body is empty. Passing a
value as a function argument counts as a use, so a =[[nodiscard]]= result is
consumed without a warning. It is =constexpr= and =noexcept=, and because the
body does nothing the compiler inlines it away to nothing.

For a *named* declaration that merely might go unused, the standard
=[[maybe_unused]]= attribute on the declaration is the right tool; =discard= is
for an *unnamed* result, or for marking an existing variable as deliberately
touched.

* API tour

- =discard(args...)= : evaluates every argument, in order, and discards the
  results. =constexpr=, =noexcept=, variadic.

That is the whole surface. There is no return, no state, and no configuration.

* Usage

#+BEGIN_SRC cpp
// Drop a [[nodiscard]] result we do not need.
nexenne::utility::discard(try_reserve(buffer, 1024));

// Evaluate several side-effecting calls and drop all their results at once.
nexenne::utility::discard(bump(), bump());

// For a named declaration that might be unused, prefer the attribute:
[[maybe_unused]] std::size_t const cap{buffer.capacity()};
#+END_SRC

* Pitfalls

- *It forces evaluation, it does not suppress it.* Every argument is computed;
  =discard= only drops the value afterwards.
- *It is not a lint silencer beyond unused results.* It does not quiet "this
  could be =const=" or similar diagnostics, only the unused-value and
  =[[nodiscard]]= warnings.
- *Not for a volatile read that must stay observable.* Binding to a reference
  does not perform a =volatile= load, so =discard= is the wrong tool for a
  benchmark sink that must force a memory read.

* Comparison with the standard library

| technique                         | greppable | evaluates | style-guide status |
|-----------------------------------+-----------+-----------+--------------------|
| =discard(x)= (this)               | yes       | yes       | required           |
| =(void)x=                         | no        | yes       | banned             |
| =static_cast<void>(x)=            | no        | yes       | banned             |
| =[[maybe_unused]]= on a name      | n/a       | n/a       | preferred for names |

The standard library has no equivalent named helper: the closest tools are the
two void casts this type replaces, and the =[[maybe_unused]]= attribute for
named declarations. Reach for =discard= to drop an unnamed value, and for
=[[maybe_unused]]= when the entity has a name and simply might not be read.
