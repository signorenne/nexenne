#+TITLE: defer
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

* Purpose

=nexenne::utility::defer= is an RAII scope-exit guard that stores a no-argument
callable and invokes it exactly once when it leaves scope. The cleanup always
runs, on a normal fall-through, an early =return=, a =break=, or an exception,
so a resource with no destructor of its own still gets released on every path.

* The problem it solves

C-style APIs hand back a resource with no RAII wrapper: a file descriptor from
=open=, a lock taken by hand, a flag that must be restored, a buffer from
=malloc=. Releasing it correctly means repeating the cleanup at every exit of
the scope, and one forgotten =return= leaks. The alternatives cost more than
they save:

- A hand-written cleanup at each =return= is duplicated and drifts out of sync
  as the function grows a new exit path.
- A =try= / =catch= that runs cleanup and rethrows handles the throwing path
  but not the early returns, and buries the logic.
- A bespoke RAII class per resource is correct but heavy for a one-off handle.

=defer= collapses this to one line placed next to the acquisition: write the
cleanup once, bind it to the scope, and every exit runs it. The price is that
it is deliberately unconditional. When the cleanup must sometimes be cancelled,
use [[file:scope_guard.org][scope_guard]] instead.

* How it works

** The wrapper

=defer= moves the callable into a member and runs it from its destructor:

#+BEGIN_EXAMPLE
template <typename Fn> class defer {
  Fn m_fn;
public:
  ~defer() noexcept(noexcept(m_fn())) { m_fn(); }
};
#+END_EXAMPLE

Class template argument deduction (the guide =defer(Fn) -> defer<Fn>=) lets you
write =defer{lambda}= without naming the closure type. The callable is stored
by value, not type-erased, so a capturing lambda inlines with no
=std::function= indirection. The guard is =[[nodiscard]]= so a bare temporary
=defer{...};= (which would construct and immediately destruct, firing the
cleanup on the spot) is a compile-time warning: always name it, as in
=auto const guard{defer{...}};=.

** Non-copyable and non-movable

The guard is tied to the exact scope where it is declared: it deletes its copy
operations, which also suppresses the move operations. That is what makes "runs
once, at this scope's exit" a guarantee rather than a hope, and it is why a
=defer= cannot be returned from a factory or stored in a container.

** The construction leak guard

Following P0052, if moving the callable into the member throws, the cleanup
must not be silently lost. The private =guarded_move= invokes the callable
immediately through the still-intact argument and then lets the exception
propagate, so no guard is left half-built and no cleanup vanishes. The catch
path is compiled only when the move can actually throw, so a nothrow callable
pays nothing.

** The conditionally-noexcept destructor

The destructor is =noexcept(noexcept(m_fn()))=: it is =noexcept= exactly when
the callable is. On a normal scope exit a throwing cleanup propagates its
exception to the caller. If the same cleanup throws while the destructor runs
during stack unwinding (an exception is already in flight), the program
terminates, per the standard destructor-throws rule. Keep the cleanup
non-throwing.

* API tour

- =defer(Fn fn)= : moves =fn= in; the guard will invoke it at scope exit.
- =~defer()= : runs the callable exactly once; conditionally =noexcept=.
- deduction guide =defer(Fn) -> defer<Fn>= : write =defer{lambda}= directly.
- =function_type= : the stored callable type =Fn=.

There is no =dismiss=, no =release=, and no way to query state: =defer= does one
thing. For cancellable cleanup, reach for [[file:scope_guard.org][scope_guard]].

* Usage

Place the guard on the line right after the acquisition, so no exit path can
forget it. Guards run in reverse order of declaration, matching the natural
unwind of nested resources:

#+BEGIN_SRC cpp
int const fd{open_connection(host)};
auto const closer{nexenne::utility::defer{[&] { close_connection(fd); }}};

lock_region();
auto const unlocker{nexenne::utility::defer{[&] { unlock_region(); }}};

// ... work that may return early or throw ...
// On every exit: unlock_region() runs, then close_connection(fd).
#+END_SRC

* Pitfalls

- *It always fires.* There is no way to cancel the cleanup. If you need
  commit-or-rollback (run only on failure), use
  [[file:scope_guard.org][scope_guard]] and =dismiss= it on success.
- *Throwing cleanup during unwinding terminates.* A cleanup that throws while an
  exception is already propagating ends the program. Keep it =noexcept= in
  practice.
- *Bind it to a name.* The guard is =[[nodiscard]]= and non-movable. A discarded
  temporary fires at the end of the full expression, not at scope exit, and
  warns; you cannot return it or store it.
- *Watch dangling captures.* A =[&]= capture must outlive the scope, which it
  does here since the guard shares that scope. Do not capture by reference a
  local that is destroyed before the guard, and do not move a =defer= out to a
  wider scope (it cannot be moved anyway).
- *Scope, not function.* The guard fires at the end of its enclosing block. A
  guard in an =if= body runs when that body ends, which is usually what you
  want, but place it deliberately.

* Comparison with the standard library

| facility                        | cancel   | owns a value | since        |
|---------------------------------+----------+--------------+--------------|
| =defer= (this)                  | no       | no           | now          |
| =scope_guard= (sibling)         | yes      | no           | now          |
| =std::experimental::scope_exit= | yes      | no           | LFS v3       |
| =unique_resource= (sibling)     | via release | yes       | now          |

=defer= is the always-run member of the P0052 scope-guard family. It matches
=std::experimental::scope_exit= in intent but drops the =release= (dismiss)
call, so it is strictly the unconditional case: choose it when the cleanup has
no reason to be cancelled, and choose [[file:scope_guard.org][scope_guard]] when
it does. Neither owns a value; to own a handle and run a deleter on it, use
[[file:unique_resource.org][unique_resource]].
