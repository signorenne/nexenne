#+TITLE: format
#+OPTIONS: toc:nil num:nil ^:nil
#+STARTUP: showall

* Purpose

=format.hpp= holds the three formatting layers for the chrono types: a
=std::formatter= specialisation, so =std::format("{}", x)= and =std::print=
accept them, and a =to_string= and an =operator<<= that give the formatter's
default text. It is separate from the
type headers because =<format>= is heavy: =static_stopwatch=, =deadline= and
=interval= are meant for small microcontrollers, and code that only times
things does not pay for it. Include =format.hpp= (or the =chrono.hpp= umbrella)
where the printing happens.

* What it provides

| type                            | renders                           |
|---------------------------------+-----------------------------------|
| =duration_parts=                | its components, as =format= would |
| =stopwatch=, =static_stopwatch= | the elapsed time                  |
| =countdown=                     | the time remaining                |
| =deadline=                      | the time remaining                |
| =interval=                      | the time until the next tick      |
| =stopwatch_state=               | the enumerator name               |
| =countdown_state=               | the enumerator name               |
| =alarm_mode=                    | the enumerator name               |

Every one renders through =nexenne::chrono::format= (see
[[file:duration-helpers.org][duration helpers]]); a leading =!= in the spec, as in ={:!}=, disables
suppress-zero and shows every component.

The stateful engines print a one-line summary of what their =const= accessors
expose. Their formatters inherit the string formatter, so a width or alignment
spec applies to the whole line:

| type                 | example                                                    |
|----------------------+------------------------------------------------------------|
| =alarm=              | =alarm(armed, mode=periodic, next_fire_time=02s)=          |
| =basic_manual_clock= | =manual_clock(now=01s:250ms)=                              |
| =frame_timer=        | =frame_timer(frames=3, fps=10)=                            |
| =hertz=              | =hertz(1000)=                                              |
| =profiler_stats=     | =profiler_stats(count=2, total=3.00 ms, ...)=               |
| =profiler=           | =profiler{"decode": profiler_stats(...)}=                  |
| =rate_limiter=       | =rate_limiter(capacity=10, refill_rate=2.5)=               |
| =scope_timer=        | =scope_timer(elapsed=01s:250ms)=                           |

A disarmed =alarm= leaves out =next_fire_time=, which is the absolute time since
the clock epoch while armed. A =profiler_stats= bucket renders its durations
through =format_scaled=, so a microsecond sample keeps its resolution, and an
empty bucket prints only =count=0=. A =rate_limiter= prints no token count:
reading it refills the bucket, so it has no =const= accessor.

=to_string(x)= returns that text as a =std::string= and =operator<<= streams it;
both use the default spec, so neither takes the =!= flag. The three enums'
=to_string= returns a =constexpr= =std::string_view=, also from =format.hpp=,
and their formatter takes a string spec such as ={:>9}=. The state enums sit at
namespace scope rather than inside the class templates, because a formatter
cannot be specialised for a type nested in a template; each class still names
its enum as =state=. For the same reason the profiler bucket is the
namespace-scope =profiler_stats=, which =profiler= names as =stats=.

* Usage

#+BEGIN_SRC cpp
#include <nexenne/chrono/format.hpp>
#include <nexenne/chrono/stopwatch.hpp>

nexenne::chrono::stopwatch<> sw;
sw.start();
// ... work ...
std::println("took {}", sw);  // for example "00s:060ms"
std::cout << sw << '\n';       // the same text
#+END_SRC

* Gotchas

- *Include it where you format.* Without =format.hpp= a =std::format= call or
  a stream insertion on one of these types does not compile; nothing falls back
  silently.
- *A running timer prints the moment it is formatted.* =to_string= reads the
  clock, so two calls on a running =stopwatch= can differ.
- *=format= and =format_scaled= stay in =duration_parts.hpp=.* They build a
  =std::string= directly and do not need this header.
